# 교대근무 데이터 형식 (DeskCal ↔ 근무 API)

DeskCal 이 교대근무 데이터를 어떤 모양으로 쓰는지, 그리고 근무를 API 로 줄 때 맞출 형식을 정리한 문서입니다.
공휴일 API(`/holidays/KR/{year}`)와 같은 방식으로 받습니다.

- 교대근무는 **사업장마다 다릅니다** (크게 두 묶음). 설정에서 사업장을 고르면 그 사업장의 근무만 받아서 보여 줍니다.
- 앱은 `GET {HOLIDAY_API_BASE}/shifts/sites` 로 사업장 목록을, `GET {HOLIDAY_API_BASE}/shifts/{year}?site={id}` 로 근무를 받아 DB 에 두고 씁니다 (3장).
- API 값이 없는 날(서버가 아직 없거나 그 날짜를 주지 않았을 때)은 그 사업장의 계산 순서로 보여 주고, 순서가 없는 사업장이면 그날은 표시하지 않습니다 (1장).

---

## 1. 앱이 쓰는 근무 데이터

### 사업장

설정 → 교대근무 → 사업장에서 고릅니다. 버튼은 사업장 목록의 순서대로 나옵니다.

- 목록은 근무 API(`/shifts/sites`, 3-1)에서 받습니다.
- 서버가 목록을 주지 않으면(`404` 또는 빈 목록) 앱에 들어 있는 기본 두 묶음을 씁니다.

  | id | 버튼 문구 | API 값이 없는 날 |
  |---|---|---|
  | `1` | 1그룹 | 기본 순서로 계산 (이 장 끝) |
  | `2` | 2그룹 | 표시하지 않음 |

- 아직 고르지 않았거나 고른 사업장이 목록에서 사라지면 목록의 첫 사업장을 씁니다.
- 사업장이 하나뿐이면 설정에 사업장 줄이 나오지 않습니다.

### 조

`A`, `B`, `C`, `D` 네 조. 순서는 항상 A → B → C → D 입니다. 모든 사업장이 같습니다.

### 근무 코드

| 코드 | 뜻 | 한 조만 볼 때 문구 | 글자색 |
|---|---|---|---|
| `D` | Day | Day | `#FFD447` 노란 금색 |
| `S` | Swing | Swing | `#FF8A4C` 주황 |
| `G` | Graveyard | Gy | `#8C9BFF` 남보라 |
| `휴` | 휴무 | 휴무 | `#4CD787` 초록 |
| 그 밖 | API 가 준 글자 그대로 | 글자 그대로 | `#B0B8D0` 회색 |

### 하루치 데이터

사업장 하나의 날짜 하나에 **조 넷의 근무 코드**가 하나씩 붙습니다.

```
1그룹  2026-11-06  →  A: D   B: S   C: G   D: 휴
```

### 화면에 나오는 곳

설정 → 교대근무 → 표시할 조에서 `전체` 또는 A·B·C·D 중 여러 조를 고릅니다.

| 고른 조 | 달력 칸 날짜 줄 오른쪽 | 일정 보기 창 제목 |
|---|---|---|
| 전체 | `D  S  G  휴` | `2026-11-06 (금)  ·  D  S  G  휴` |
| B, D | `_  S  _  휴` (A·C 자리는 빈칸) | `2026-11-06 (금)  ·  B조 Swing  D조 휴무` |
| B 하나 | `Swing` | `2026-11-06 (금)  ·  B조 Swing` |

- 여러 조일 때는 A·B·C·D 네 자리가 날마다 같은 자리에 있고, 고르지 않은 조는 빈칸입니다.
- 배지에 마우스를 올리면 고른 조를 풀어서 보여 줍니다 (`B조 Swing` / `D조 휴무`).
- API 에서 그날 어떤 조가 빠졌으면 그 자리는 `-` 입니다. 한 조 보기에서는 배지가 나오지 않습니다.
- API 값도 계산 순서도 없는 날은 배지와 제목의 근무가 모두 나오지 않습니다.

### API 값이 없는 날의 계산

사업장마다 계산 순서(`rule`)를 둘 수 있습니다. 서버가 사업장 목록에 함께 줍니다 (3-1).

```
n    = (날짜 - baseDate) 일수
L    = rotation 길이
조 k = rotation[(start[k] + n) mod L]        k: A=0, B=1, C=2, D=3
```

- `baseDate`: 계산 기준일. 이 날 조 k 는 `rotation[start[k]]` 근무입니다.
- `rotation`: 하루씩 넘어가는 근무 순서.
- `start`: 기준일에 각 조가 서 있는 `rotation` 칸. 빼면 조마다 `L/4` 칸씩 앞섭니다 (이때 `L` 은 4의 배수).
  - 예: `rotation` 이 `D D S S G G 휴 휴` 처럼 8칸이고 `start` 를 빼면 A 0, B 2, C 4, D 6 칸입니다.

기본 순서 (기본 두 묶음의 1그룹):

- `baseDate` `2026-11-06`, `rotation` `D → S → G → 휴`, `start` A 0, B 1, C 2, D 3.
- 기준일에 A·B·C·D조가 `D`·`S`·`G`·`휴` 이고, 다음 날 모두 한 칸씩 넘어갑니다 (`ShiftSchedule.DefaultRule`).

설정에서 순서를 바꾸는 곳은 없습니다. 실제 근무는 API 로 주세요.

### 저장하는 곳

| 위치 | 내용 |
|---|---|
| settings 테이블 `ShiftEnabled` | `1` / `0` (교대근무 표시) |
| settings 테이블 `ShiftTeam` | `All` 또는 고른 조를 쉼표로 (`B,D`) |
| settings 테이블 `ShiftSite` | 고른 사업장 `id` (비면 첫 사업장) |
| settings 테이블 `ShiftSites` | 마지막으로 받은 사업장 목록 응답 JSON (비면 기본 두 묶음) |
| `shifts` 테이블 | API 로 받은 근무. `site` (사업장 `id`), `date_key` (`yyyy-MM-dd`), `team` (`A`~`D`), `code` |

DB 는 `C:\Deskcal\deskcal.db` 입니다. 6.2.2 이하에서 받아 둔 근무(사업장 칸 없음)는 처음 켤 때 1그룹(`1`) 것으로 옮깁니다.

근무 API 도 이 모양을 그대로 따릅니다.

## 3. 근무 API 형식

- 공휴일과 같은 서버, 같은 주소입니다 (지금은 `http://localhost:8765`).
- 인증은 없습니다 (공휴일과 같음).
- 응답은 `200 OK`, `Content-Type: application/json; charset=utf-8` 입니다.
- 필드 이름의 대소문자는 가리지 않습니다 (공휴일 응답과 같음).
- 문자열은 UTF-8 입니다. `"휴"` 를 `"\ud734"` 처럼 이스케이프해서 보내도 됩니다.

### 3-1. 사업장 목록

```
GET {HOLIDAY_API_BASE}/shifts/sites
```

```json
{
  "sites": [
    {
      "id": "1",
      "name": "1그룹",
      "rule": { "baseDate": "2026-11-06", "rotation": ["D", "S", "G", "휴"] }
    },
    { "id": "2", "name": "2그룹" }
  ]
}
```

| 필드 | 형식 | 설명 |
|---|---|---|
| `sites` | 배열 | 사업장. 이 순서대로 설정에 버튼이 나오고, 첫 사업장이 기본 |
| `sites[].id` | 문자열 | 근무 요청의 `site` 값. 주소에 들어가니 영문·숫자·`-` 로 짧게 |
| `sites[].name` | 문자열 | 설정 버튼 문구. 버튼이 좁으니 짧게 (비면 `id`) |
| `sites[].rule` | 객체, 생략 가능 | API 값이 없는 날의 계산 순서 (1장). 없으면 그런 날은 표시하지 않음 |
| `rule.baseDate` | `"yyyy-MM-dd"` 문자열 | 계산 기준일 |
| `rule.rotation` | 문자열 배열 | 하루씩 넘어가는 근무 코드 순서 |
| `rule.start` | 객체, 생략 가능 | `{ "A": 0, "B": 1, "C": 2, "D": 3 }` 처럼 기준일에 각 조가 서 있는 `rotation` 칸. 주면 네 조 모두 |

규칙:

1. `id` 가 비었거나 앞 사업장과 겹치는 항목은 무시합니다.
2. `rule` 형식이 틀리면(날짜 형식, 빈 `rotation`, `start` 에 빠진 조, `start` 없이 4의 배수가 아닌 길이) `rule` 이 없는 것으로 봅니다.
3. **사업장 구분이 없는 서버**는 `404` 를 주면 됩니다. 앱은 기본 두 묶음(`1`, `2`)을 쓰고, 근무 요청에 `site=1` 또는 `site=2` 를 붙입니다.
   - `200` 에 `sites` 를 빈 배열로 줘도 같습니다.
4. 연결 실패, 시간 초과, 그 밖의 응답이면 전에 받아 둔 목록을 그대로 씁니다.
5. 서버에서 `/shifts/{year}` 보다 **먼저 등록**하세요. 경로가 겹쳐서 `sites` 가 연도로 읽힐 수 있습니다 (4장 예시 참고).

### 3-2. 근무

```
GET {HOLIDAY_API_BASE}/shifts/{year}?site={id}
```

- `year` 는 4자리 연도입니다. 예: `/shifts/2026?site=2`
- `site` 는 고른 사업장의 `id` 입니다. 앱은 늘 붙여서 보냅니다.
  - 서버는 `site` 마다 그 사업장의 근무를 줘야 합니다. `site` 를 무시하면 모든 사업장에 같은 근무가 보입니다.
  - 모르는 `site` 는 `404` 를 주세요.

```json
{
  "year": 2026,
  "site": "1",
  "shifts": [
    { "date": "2026-11-05", "teams": { "A": "휴", "B": "D", "C": "S", "D": "G" } },
    { "date": "2026-11-06", "teams": { "A": "D", "B": "S", "C": "G", "D": "휴" } },
    { "date": "2026-11-07", "teams": { "A": "S", "B": "G", "C": "휴", "D": "D" } },
    { "date": "2026-11-08", "teams": { "A": "G", "B": "휴", "C": "D", "D": "S" } },
    { "date": "2026-11-09", "teams": { "A": "휴", "B": "D", "C": "S", "D": "G" } }
  ]
}
```

| 필드 | 형식 | 설명 |
|---|---|---|
| `year` | 정수 | 요청한 연도 |
| `site` | 문자열, 생략 가능 | 요청한 사업장 `id` (앱은 읽지 않음, 확인용) |
| `shifts` | 배열 | 하루에 한 항목. 날짜 순서는 상관없음 |
| `shifts[].date` | `"yyyy-MM-dd"` 문자열 | 공휴일 `date` 와 같은 형식 |
| `shifts[].teams` | 객체 | 키는 조 `"A"` `"B"` `"C"` `"D"`, 값은 근무 코드 |

규칙:

1. **한 해 전체를 보냅니다** (1월 1일 ~ 12월 31일).
   - 아직 정해지지 않은 날은 빼면 되고, 그날은 1장의 계산으로 보입니다 (`rule` 이 없는 사업장이면 표시 안 함).
   - 요청한 연도가 아닌 날짜는 무시합니다.
2. **날짜는 근무가 시작하는 날**입니다. 자정을 넘기는 `G`(Gy) 근무도 시작한 날짜에 둡니다.
3. **조 키는 `A`~`D`** 입니다 (소문자도 받음). 어떤 날 한 조가 빠지면 그날 그 조 자리는 `-` 입니다.
4. **근무 코드는 `D`, `S`, `G`, `휴`** 를 씁니다.
   - `d` `s` `g` 처럼 영문 한 글자 소문자는 대문자로 바꿉니다. 앞뒤 공백은 지웁니다.
   - 다른 값(예: `교`, `연`)은 글자 그대로 회색으로 보여 줍니다. 달력 칸이 좁으니 1~2글자로 해 주세요.
   - 빈 문자열이나 `null` 은 그 조가 빠진 것으로 봅니다.
5. **데이터가 없는 연도**는 `404` 를 주면 됩니다. 앱은 그 해를 건너뛰고 전에 받아 둔 값을 그대로 씁니다.
   - `200` 에 `shifts` 를 빈 배열로 주면, 그 사업장의 그 해에 받아 둔 값을 지웁니다.

### 앱이 받는 방식

- **언제**: 앱을 켤 때, 설정에서 교대근무 표시를 켤 때, 사업장을 바꿀 때 받습니다.
  - 켜 둔 채로 날이 바뀌면 한 시간 안에 다시 받습니다.
  - 서버에 연결하지 못했으면 한 시간마다 다시 시도합니다.
  - 교대근무 표시가 꺼져 있으면 요청하지 않습니다.
- **순서**: 사업장 목록(3-1)을 먼저 받고, 고른 사업장의 올해-1 ~ 올해+1 년을 한 해씩 요청합니다. 시간 제한은 10초입니다.
- **저장**: 받은 연도는 `shifts` 테이블에서 **그 사업장의 그 해 전체를 새 값으로 바꿉니다**.
  - 공휴일은 새 날짜만 더하지만, 근무는 바뀔 수 있어서 덮어씁니다.
  - 그래서 근무표를 고치면 다음 요청 때 그대로 반영됩니다.
  - 받은 값이 전과 같으면 아무것도 바꾸지 않습니다.
  - 다른 사업장의 받아 둔 값은 남아 있어서, 다시 고르면 서버가 꺼져 있어도 바로 보입니다.
- **실패할 때**: 연결 실패, 시간 초과, `200` 이 아닌 응답, JSON 형식 오류면 그 해는 건너뛰고 전에 받아 둔 값을 씁니다.
- **API 에 없는 날**: 1장의 계산(그 사업장의 `rule`)으로 보여 줍니다.

## 4. 서버 예시 (FastAPI)

아래 예시는 1그룹을 1장의 기본 순서로 계산해서 돌려줍니다.
2그룹은 근무표가 정해지면 `rule` 을 채우거나, `teams_for` 에서 실제 근무 데이터를 돌려주면 됩니다.

```python
from datetime import date, timedelta
from fastapi import FastAPI, HTTPException

app = FastAPI()

TEAMS = ["A", "B", "C", "D"]
SITES = [
    {"id": "1", "name": "1그룹",
     "rule": {"baseDate": "2026-11-06", "rotation": ["D", "S", "G", "휴"]}},
    {"id": "2", "name": "2그룹"},  # 근무표가 정해지면 rule 을 채움
]


def teams_for(site, d):
    """그날 조별 근무. 실제 근무표가 있으면 여기서 그 값을 돌려줌. 예시는 rule 로 계산"""
    rule = site.get("rule")
    if not rule:
        return None
    rot = rule["rotation"]
    n = (d - date.fromisoformat(rule["baseDate"])).days
    start = rule.get("start") or {t: k * len(rot) // 4 for k, t in enumerate(TEAMS)}
    return {t: rot[(start[t] + n) % len(rot)] for t in TEAMS}


@app.get("/shifts/sites")  # /shifts/{year} 보다 먼저
def sites():
    return {"sites": SITES}


@app.get("/shifts/{year}")
def shifts(year: int, site: str):
    s = next((x for x in SITES if x["id"] == site), None)
    if s is None:
        raise HTTPException(404)
    out, d = [], date(year, 1, 1)
    while d.year == year:
        teams = teams_for(s, d)
        if teams:
            out.append({"date": d.isoformat(), "teams": teams})
        d += timedelta(days=1)
    return {"year": year, "site": site, "shifts": out}
```

## 5. 맞춰 볼 값

1그룹 (기본 순서):

| 날짜 | A | B | C | D | 달력 칸 (전체) |
|---|---|---|---|---|---|
| 2026-01-01 | 휴 | D | S | G | `휴 D S G` |
| 2026-11-05 | 휴 | D | S | G | `휴 D S G` |
| 2026-11-06 | D | S | G | 휴 | `D S G 휴` |
| 2026-11-07 | S | G | 휴 | D | `S G 휴 D` |
| 2026-11-08 | G | 휴 | D | S | `G 휴 D S` |
| 2026-12-31 | 휴 | D | S | G | `휴 D S G` |

이 순서에서는 어느 날이든 `D`·`S`·`G`·`휴` 가 한 조씩입니다.
실제 근무 데이터는 특근 같은 예외가 있어도 그대로 보내면 됩니다. 앱은 이 규칙을 검사하지 않습니다.

예를 들어 아래처럼 보내면:

```json
{ "date": "2026-11-10", "teams": { "A": "교", "B": "D", "C": "S" } }
```

달력에는 `교 D S -` 로 보입니다. `교` 는 회색이고, 빠진 D조 자리는 `-` 입니다.

`start` 를 쓰는 `rule` 예: 기준일에 A·B·C·D조가 `D`·`휴`·`G`·`S` 이면

```json
{ "baseDate": "2026-11-06", "rotation": ["D", "S", "G", "휴"], "start": { "A": 0, "B": 3, "C": 2, "D": 1 } }
```

다음 날(11-07)은 A `S`, B `D`, C `휴`, D `G` 입니다.
